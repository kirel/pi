## First login

1. As Daniel, open `https://id.kirelabs.org`, Users, and the three-dot menu for
   Hausfee or Sabine. Choose **Login Code**, set an expiry and generate the link.
2. Open the link in the intended user's browser profile and enroll a passkey.
   Daniel manages Hausfee's passkey; Sabine enrolls her own. Existing accounts
   should be used, not recreated with signup links.
3. Open `https://litellm.kirelabs.org/ui` in that same browser profile and sign
   in through Pocket ID with the corresponding identity.
4. Open the MCP connections view, connect `craft_family`, sign into Craft and
   select the **Family Space**. The selected Craft account needs access to that
   space; a Pocket ID account does not create a Craft account or membership.
5. Repeat for each identity. Verify a read-only Family document lookup after
   consent, and refresh/reconnect behavior before calling onboarding complete.

## Declarative sources and deployment

- `group_vars/all/litellm_family.yml`: stable identities and existing key bindings.
- `group_vars/all/pocket_id.yml`: LiteLLM's allowed SSO groups.
- `roles/llm_tools/defaults/main.yml`: central MCP catalog.
- `group_vars/all/hermes_mcp.yml`: personally scoped team/key permissions.
- `group_vars/hetzner.yml`: persistent Docker user/team bindings and OAuth opt-in.
- `roles/pocket_id/files/family-users.py`: creates missing accounts and adds
  Family group membership; refuses conflicting identities without replacing them.
- `roles/llm_tools/files/family-access.py`: provisions SSO subjects and binds
  existing keys while preserving other permissions.

```bash
uv run ansible-playbook setup.yml --tags pocket-id --limit homelab
uv run ansible-playbook setup.yml --tags llm-tools --limit homelab --extra-vars '{"llm_tools_compose_services":["litellm-proxy"]}'
uv run ansible-playbook setup.yml --tags hermes-oauth --limit ubuntu-8gb-fsn1-1
```

MCP gateway admission uses `x-litellm-api-key: Bearer ${LITELLM_API_KEY}`.
The Docker default is declarative; the bare-metal opt-in task changes only this
header through Hermes CLI, preserving manual MCP entries and the rest of config.
Bare-metal secrets are hydrated by Hermes' external secret source; reading
`.env` alone does not reproduce its effective credentials.

LiteLLM's first team-permission update temporarily left an old authorization
view active. Re-running the identity/team/key phase succeeded without another
proxy restart:

```bash
uv run ansible-playbook setup.yml --tags llm-tools --limit homelab --start-at-task 'Prepare family SSO identities before team membership'
```

## OAuth client persistence (2026-09-14)

The recorded access-token lifetimes were approximately one hour. Both Craft
servers had per-user credentials but no persisted DCR client in either
`LiteLLM_MCPServerOAuthClient` or a database server record. This is consistent
with refresh failing after interactive registration by a non-admin user.
Installed LiteLLM 1.99.1 already contains the config-server persistence support
from https://github.com/BerriAI/litellm/pull/33768; upgrading alone would not
initialize the missing registrations.

`roles/llm_tools/tasks/craft-oauth-bootstrap.yml` registers both config-defined
servers through the admin OAuth management endpoint. Stable server IDs live in
`group_vars/all/litellm_family.yml`. Client credentials remain encrypted in
LiteLLM's database; Ansible suppresses registration results and reuses existing
registrations on later runs. Database inspection after deployment confirmed a
stored client ID for both servers without inspecting credential values.

```bash
uv run ansible-playbook setup.yml --tags litellm-oauth-bootstrap --limit homelab
```

Existing user grants may belong to the earlier ephemeral clients. Reconnect
